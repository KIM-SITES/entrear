
# AGENTS.md — Demo Climatização

## Contexto

Este repositório será utilizado para desenvolver um website demonstrativo de uma empresa fictícia de climatização.

O projeto fará parte do portfólio comercial de um desenvolvedor independente que pretende oferecer sites profissionais para pequenas empresas brasileiras.

O website deve demonstrar um nível elevado de qualidade visual, experiência de usuário e desenvolvimento front-end.

A empresa é fictícia. Não apresentar depoimentos, certificações, prêmios, clientes ou resultados inventados como reais.

## Papel do Codex

Atue como um time multidisciplinar, considerando as perspectivas de:

- Diretor de arte digital
- Designer de identidade visual
- UI/UX Designer
- Motion Designer
- Desenvolvedor Front-End
- Especialista em acessibilidade e performance

Esses papéis representam perspectivas de análise, não exigem múltiplos agentes simultâneos.

Não aceite automaticamente a primeira solução visual.

Analise alternativas, critique ideias previsíveis e proponha soluções fundamentadas.

## Direção criativa

O objetivo é produzir uma experiência visual memorável, coerente e comercialmente eficiente.

Evite reproduzir automaticamente padrões comuns de sites gerados por IA, como:

- Hero genérico com título, subtítulo e dois botões
- Gradientes decorativos sem justificativa
- Três cards idênticos para todos os serviços
- Glassmorphism indiscriminado
- Excesso de bordas arredondadas
- Sombras repetitivas
- Tipografia sem personalidade
- Fotografias genéricas sem direção artística
- Animações iguais em todas as seções
- Layouts sem variação de composição
- Textos publicitários artificiais

Esses elementos não são absolutamente proibidos. Utilize-os apenas quando contribuírem para a identidade e a experiência.

Priorize:

- Direção artística própria
- Tipografia expressiva
- Composição intencional
- Hierarquia visual clara
- Espaçamento consistente
- Fotografia bem selecionada
- Ritmo entre seções
- Microinterações significativas
- Animações planejadas
- Excelente experiência em dispositivos móveis

## Skills

Utilize a Skill `frontend-design` durante a exploração criativa e a implementação visual, quando apropriado.

Utilize a Skill `web-design-guidelines` para revisar a interface e identificar problemas de experiência, acessibilidade e boas práticas.

Não trate sugestões das Skills como regras absolutas quando entrarem em conflito com requisitos do projeto.

## Processo obrigatório

### 1. Planejamento

Antes de implementar, definir:

- Objetivo comercial
- Público-alvo
- Identidade da empresa fictícia
- Referências visuais
- Direção artística
- Estrutura das páginas
- Linguagem de movimento
- Tecnologias adequadas

### 2. Exploração criativa

Apresentar pelo menos três direções visuais substancialmente diferentes.

Explicar as vantagens, desvantagens e complexidade de cada uma.

Aguardar aprovação antes de implementar.

### 3. Desenvolvimento

Implementar em etapas pequenas e verificáveis.

Preservar a direção artística aprovada.

Organizar componentes e arquivos de maneira profissional.

Evitar dependências desnecessárias.

### 4. Validação

Verificar:

- Responsividade
- Acessibilidade
- Performance
- Legibilidade
- Funcionamento dos links
- Navegação por teclado
- Compatibilidade entre navegadores
- Comportamento das animações
- Consistência visual

Respeitar `prefers-reduced-motion`.

### 5. Revisão visual

Sempre que possível, analisar capturas reais da interface no navegador.

Não considerar o projeto concluído apenas porque compila.

Identificar elementos genéricos, inconsistências e oportunidades de refinamento.

## Tecnologias

Não limitar a implementação às tecnologias já conhecidas pelo proprietário do projeto.

Escolher a stack considerando qualidade, desempenho, manutenção, hospedagem e facilidade de reutilização.

Não adicionar ferramentas apenas por popularidade.

## Assets e conteúdo

Utilizar somente imagens, fontes e recursos com licenças compatíveis com o uso pretendido.

Não copiar integralmente designs de terceiros.

Não inventar dados comerciais reais.

Identificar claramente que o projeto é demonstrativo.

## Controle de alterações

- Não realizar commits automaticamente.
- Não executar push.
- Não criar repositórios remotos sem autorização.
- Não realizar deploy sem autorização.
- Não apagar arquivos importantes sem aprovação.
- Explicar alterações significativas.

Ao concluir cada etapa de implementação, sugerir uma mensagem de commit semântico em português.

## Comunicação

Responder em português brasileiro.

Justificar decisões técnicas e visuais importantes.

Apresentar críticas construtivas e específicas.

Evitar elogios automáticos e avaliações superficiais.

Não avançar para a próxima etapa sem minha autorização.
